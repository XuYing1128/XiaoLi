# 中转站黑盒审计：方法、证据与限制

小狸的中转审计用来发现可复现的协议矛盾、疑似过量计数、多能力域降质和与匹配参考分布的显著差异。它不声称 100% 确认物理模型，也不使用“看起来像某模型”代替可复核证据。

## 威胁模型

小狸希望发现：

- 返回值与宣称的 OpenAI Responses、OpenAI Chat Completions 或 Anthropic Messages 契约不一致。
- `usage` 内部算术不可能，或在多个受控输入量级上稳定高于匹配基线/可解释区间。
- 已实现的结构化 JSON、工具选择、长上下文随机 nonce 检索、算术/约束推理、同请求多消息状态或多语言中至少两个独立能力域持续退化。
- 单 Token 分布与精确模型/参数匹配的参考分布显著不同。
- 固定答案缓存导致的分布塌缩，以及原题正常而语义改写题明显退化。
- 主动审计与真实 Codex 回合可在同一本地 `RelayProfile` 上保守对照：仅匹配会话绑定的 endpoint 分类与内存 endpoint 作用域指纹，只持久化 profile ID。作用域由规范化协议、主机、有效端口和 API 基础路径组成，不含 userinfo、query 或 fragment。它是独立的“疑似选择性服务”警告，不改写四轴或总结论。

无法排除的对手能力：中转控制完整请求/响应链，可以从 TLS、IP、客户端特征、频率或题型识别所有审计流量，并只在检测期选择性转发真实模型。对这种情况，纯黑盒客户端不存在不可规避保证。

### 真实会话对照

为了发现“审计期表现正常，真实使用长期异常”的矛盾，小狸维护一条不改写四轴的独立证据：

- 仅处理自定义、托管或本地 endpoint；官方登录/API 不适用。
- 同一回合的连接分类和 endpoint 作用域指纹必须与一个且仅一个已保存 profile 精确匹配；配置与 hook 证据冲突、同作用域多 profile 或证据缺失都不绑定。
- endpoint 作用域指纹只在采集刷新期间存于内存；SQLite、报告和 MCP 只看到本地 profile ID。
- 仅当本次主动审计的 `overallVerdict` 为 `consistent` 时，才对照同 profile 最近 30 天已完成的真实回合。
- 至少 10 个已完成回合，且至少 5 个、占比不低于 50% 的回合仍保留 `suspected_degradation` 警告，才生成黄色 `suspectedSelectiveService`。
- 它永远不会把 `overallVerdict` 改成另一种结果，也不会生成 `actualModel`。

工具调用、缓存、输入分布、网络和上游负载都可能使真实回合与主动探针不同。这个黄色状态表示需要复核的统计矛盾，不是“选择性路由实锤”。

## 四条独立证据轴

### 1. 协议兼容

检查 HTTP 状态、Content-Type、结构化响应包络、SSE 终止、自报模型与请求模型的精确规范化比较。

- 正常：本次选定协议范围内没有矛盾。
- 异常：可复现的包络/SSE/自报型号契约矛盾。
- 无法检查：认证、网络、限流或协议不支持让证据不足。

自报模型是协议字段，不是物理模型证书。

### 2. 计量一致性

首先检查不需要基线的算术不变式：

- 任何 Token 字段不能为负数。
- `cached_input_tokens <= input_tokens`。
- `reasoning_output_tokens <= output_tokens`。
- `total_tokens >= input_tokens + output_tokens`，且不能整数溢出。
- 流式终态 usage 与同一请求内的结构化组成项不能自相矛盾。

然后在 256 / 1024 / 4096 Token 量级上执行随机受控输入，区分流式与非流式。疑似过量计数至少要求：

- 每个量级有足够配对样本。
- 至少两个独立输入量级的 bootstrap 区间都稳定超出参考与容差。
- 报告保留隐藏 system prompt、reasoning、provider 包装和缓存语义的限制。

只有算术不可能才是红色契约矛盾。超出本地 tokenizer 估算不等于“偷 Token 实锤”。对已知 OpenAI tokenizer 可使用本地 `tiktoken-rs`；未知别名和 Anthropic 不声称本地绝对计数精确。

### 3. 行为质量

质量探针只使用本地确定性 scorer，首版不使用会被提示注入影响的 LLM judge，也不执行模型返回的工具调用、代码或命令。

`v0.2.0-beta.1` 实际实现的能力域是：

- 结构化 JSON 和 schema 约束。
- 长上下文随机 nonce 检索。
- 算术与约束推理。
- 多语言等价任务。
- 工具选择：按 OpenAI Responses、OpenAI Chat Completions 或 Anthropic Messages 的协议发送真实工具 schema；只在本地比较结构化工具名和参数。
- 状态保持：在同一个 API 请求所携带的 `system / user / assistant / user` 多消息历史中放置随机状态，再要求返回指定字段。

工具调用始终作为不可信结构化数据处理，只解析并比较受限的函数名和字符串参数，绝不执行，也不能触发 URL、脚本、代码、命令或二次工具；评分后不持久化原始响应正文。状态保持只验证端点能否正确处理这一次请求中明确提供的消息历史，不跨越两个网络请求，不测试 provider 服务端会话存储，更不是跨网络会话或物理模型证明。

启用实时官方配对时，“疑似降质”要求至少两个独立能力域越过配对参考的保守容差，并在两个独立检查批次持续出现。未启用官方配对时仍会采集目标端探针，但当前 beta 不把它们评分为“相对官方模型一致/降质”，行为质量保持学习中/证据不足。单一速度、文风、知识题、拒答话术或缓存变化不能触发。

快速档每个质量域在两个批次中各只有 1 个样本，低于当前每域最少 4 个配对样本的裁决门槛，所以即使启用官方配对也只保持学习中。标准档每域每批 4 个、深度档每域每批 8 个样本，才会执行当前 99% bootstrap 质量比较。快速档的 JSD 身份比较与质量轴是两套独立证据，不能因为其中一条有结果就提升另一条。

### 用户私有 probe pack

工作台可为每个端点选择一个本地 JSON 题包。保存配置时小狸严格校验文件并只把规范化绝对路径、`version` 与 SHA-256 写入 SQLite；审计报告也只保存这三项。`prompt` 和 `expected` 只在审计开始时短暂读入内存，不进入报告、日志、事件或 SQLite。文件缺失、版本变化或 SHA-256 变化时，审计会在任何网络请求前拒绝启动；修改题包后需要在工作台重新选择并保存。

当前 schema 固定为：

```json
{
  "schemaVersion": 1,
  "version": "my-pack-v1",
  "tasks": [
    {
      "id": "arithmetic-a-01",
      "batch": "a",
      "domain": "constraintReasoning",
      "scorer": "exactText",
      "prompt": "Compute (17 × 19) + 4. Return only the integer.",
      "expected": "327",
      "maxOutputTokens": 16
    }
  ]
}
```

限制与边界：

- 文件最多 256 KiB，任务数 1–64；未知字段、重复 ID、过长字符串、过深 `exactJson` 和双向控制字符都会被拒绝。
- `domain` 只接受 `structuredOutput`、`longContextRetrieval`、`constraintReasoning`、`multilingual`。
- `scorer` 只接受 `exactText` 或 `exactJson`；评分完全在本地确定性执行，不调用 LLM judge。
- 题包任务只在质量 detector 启用且不是“连接测试”时加入随机探针计划，并与内置任务共享同一请求数、输入 Token、输出 Token 和超时硬上限。小狸不会用截断计划来静默挤掉内置或私有任务；完整计划超过任一已确认预算时会在网络请求前拒绝启动。
- 小狸只把题包文本作为模型输入、把回复作为不可信文本/JSON 比较；不会执行题包或回复中的代码、URL、工具调用、HTML 或指令。
- `batch` 用于配对质量的独立批次。私有任务能增加可复核覆盖面，但不能把“与参考一致”升级为物理模型证明。

启用全部 detector 时，当前内置计划分别使用快速 140、标准 308、深度 716 次请求/端点，因此在默认硬上限内分别可再容纳最多 10、12、4 个私有任务。工作台以实际选择的 detector 和已验证题包重新预览；超出的题包不会被部分运行。

### 4. 模型身份

单 Token 分布指纹使用 10 个任务家族（数字、字母、颜色、动物、城市、食物、情绪、形状、职业、天气）与中/英/日/西四种语言。默认每 cell 15 次采样，至少 10 个有效结果才有资格比较。

归一化处理 Unicode、全角数字、标点与已知颜色同义词，并单独统计空答、拒答和非法输出。每 cell 使用 base-2 Jensen–Shannon divergence；只有当前模型、协议、effort/采样参数和基线都匹配时，才能显示“与参考一致/显著不同”。

`v0.2.0-beta.1` 只有在用户明确配置同协议、同精确模型的第一方 profile 后，才会在同一次审计中实时调用目标端与官方端：两端使用相同 case 和参数，并随机交错顺序。配对报告计算 JSD；标准/深度档还计算带 199 次 permutation 的 MMD。没有这组实时匹配参考时，即使采集到足够 cell，模型身份轴也必须返回 `insufficientEvidence`。

## 探针随机化与可复现性

每次运行由操作系统 CSPRNG 生成 256-bit `runSeed`。该种子决定：

- 任务家族/语言组合。
- 同义改写、空白格式和受控随机数据。
- 协议、计量与指纹 case 的最终顺序。

生成规则和评分方法可公开，但仓库不包含固定的最终请求清单。报告保存 `runSeed`和参数，让用户可本地复现已知异常；重跑时默认生成新种子，避免固定题库。

## 实时官方配对、内置社区参考与导入元数据

当前版本的评分边界：

1. 只有同次运行、同 API surface、同协议、精确模型和相同探针参数的实时官方配对样本，才能作为中/高置信度统计参考。
2. Release 编译进去的版本化社区分布会与当前随机单 Token 样本计算距离。只有至少 4 个共同 cell、至少 2 个参考可比，且最近参考相对次近参考的距离改善不小于 30% 时，才显示“实验性地更接近某参考”。这些数据的原请求协议与小狸不匹配，所以置信度固定为低，不改变四条证据轴或 `overallVerdict`。
3. `RelayBaselineSummary` 的 official/community/user 导入项只保存模型、协议、版本、样本数、时效、签名标记和限制等元数据；`v0.2.0-beta.1` 不把它们喂给 scorer。用户导入默认未签名，不能替代实时官方配对。

中转样本不能写入官方/社区元数据命名空间。如果模型是浮动别名、provider 不同、参数被强制或 reasoning 被隐藏，实时配对也必须在限制中说明不可比因素并降低结论力度。

当前 beta 的一次审计只接受一个与目标声称模型完全相同的官方配对端点。内置社区参考可附加“低置信实验排名上更接近 5.5 参考样本”，但它绝不能写成 `actualModel=5.5`，也不能把身份轴或总裁决改为已验证。详细数据来源与限制见 [社区参考基线](COMMUNITY_BASELINES.md)。

## 抗提示注入和不可信输入

中转响应可能包含“忽略检测规则”、伪造工具调用、HTML/脚本、恶意 URL、双向 Unicode 控制符或超大/超深 JSON。小狸的信任边界是：

- 只把响应解析为有上限的结构化字段与短探针样本。
- 协议 scorer 不接收响应正文，正文无法改写状态机或分数。
- 前端使用文本节点渲染，不执行 HTML。
- 禁止 HTTP 重定向，API Key 只发往用户确认的原 origin。
- 单 SSE event、总响应、字符串和嵌套都有硬上限。
- 报告、日志、SQLite 和事件不保存原始回复正文或 API Key。

非 localhost 的明文 HTTP endpoint 只能在用户逐次确认后进行手动测试；定时审计会拒绝它。localhost 可用于本地 mock/开发。

## 预算、取消与重试

各档硬上限是服务器端点级别：连接 6、快速 150、标准 320、深度 720。每次网络尝试必须计数，传输适配器不得在管理器外隐藏重试。工作台确认框会单列私有题包增加的请求数和保守 Token 额度，并显示完整计划每端点请求数；启用官方配对时总操作数按两端相同计划乘以 2。

审计另有输入 Token、输出 Token 与超时上限。每次发包前，小狸会对完整线上的 system、messages、工具 schema 和私有题包输入计算保守上界：已知 OpenAI 模型使用本地 tokenizer，无法可靠映射 tokenizer 的模型按 UTF-8 字节数这一更保守界限计费；随机指纹探针会枚举有限生成面并取真实 wire body 最大值，其他随机模板保持序列化长度不变，所以任意执行 seed 的实际预留都不能超过工作台显示值。未来 `runSeed` 不会在活动任务或启动回执中提前暴露，完成报告才保存它用于复核。若完整计划不能落在用户确认的上限内，则在任何网络请求前拒绝启动。如果 provider 报告的隐藏包装用量在某次响应后仍超过本地可见上界，小狸不会开始下一次请求，并在限制中记录预算提前终止。这里不能约束服务商在不可见服务器侧额外添加的内容，因此报告会把该限制单独说明。

点击取消后取消标志立即阻止新请求。正在执行的网络 I/O 依赖平台取消/有界超时；已完成结构化证据可保留在 `cancelled` 报告。

## 报告结论

`overallVerdict` 固定为：

```text
consistent
insufficientEvidence
suspectedPadding
suspectedDegradation
significantlyDifferent
confirmedContractMismatch
failed
cancelled
```

优先级：明确契约矛盾 > 疑似过量计数 > 疑似降质 > 显著分布差异 > 证据不足 > 与参考一致。任何行为结论都不会填充 `actualModel`，也不会创建 Codex `serverRoute`。

## 正确解读一份通过报告

正确：

> 本次审计范围、参数与实时匹配参考中未发现显著异常；真实物理模型未获密码学证明。

错误：

> 小狸证明这一定是官方 Sol，且中转无法规避检测。

如果要将报告用于争议或客服申诉，应保留报告版本、endpoint 脱敏类别、精确请求模型/参数、`runSeed`、参考来源/版本、时间、四轴原因和所有限制，而不是只截取颜色或总结文案。
