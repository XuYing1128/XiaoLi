# 从解压到看到第一个活动回合

本教程带你在三步内启动小狸、连接 Codex，并正确理解第一张监视卡。

## 你需要准备

- Windows 10/11 x64、macOS 12+，或常见 x64 Linux 桌面。
- 已安装并能正常使用的 Codex。
- 从 [GitHub Releases](https://github.com/XuYing1128/XiaoLi/releases) 下载的对应便携包。
- 不需要 Node.js、管理员权限、Windows 服务或传统安装器。

## 第一步：解压并启动

Windows 解压 ZIP 后运行 `XiaoLi.exe`。macOS 解压 `.app.zip` 后将应用移到“应用程序”。Linux 解压后运行 AppImage；如果来自 ZIP，先执行：

```bash
chmod +x XiaoLi-x86_64.AppImage
```

首次启动会为当前用户写入或升级 `xiaoli-model-monitor` 插件配置。随后在 Codex 中打开 `/hooks`，审阅并信任小狸的本地 hook；小狸不会绕过 Codex 的信任确认。程序移动到其他目录后，再启动一次即可修复绝对路径，但命令哈希变化后也需要重新审阅。若 Codex 已经运行，请新建任务或重启后加载插件。

预期结果：系统托盘出现小狸图标。Codex 尚未运行时，状态为灰色“空闲”。

## 第二步：开始一个 Codex 回合

启动 Codex，打开一个任务并发送消息。小狸应在结构化事件写入后更新为紧凑卡片，例如：

```text
✓  Sol · ultra（请求）  ◇
   162.6k tok · 缓存输入 98.6%
```

这里的 `Sol` 和 `ultra` 是本回合请求值。`◇` 的完整文案是“未见服务器重路由”，不是“服务器已确认 Sol”。

如果没有出现活动回合，先点击托盘“立即刷新”，再看 [故障排查](TROUBLESHOOTING.md#codex-正在运行但没有活动会话)。

## 第三步：展开证据

点击向下箭头展开。单个根会话首次会自动打开；多个根会话默认收起，避免窗口一下变得太长。

你会看到：

- 本回合请求模型和请求 effort。
- 下一回合待生效值（如果中途切换过）。
- 显式服务器重路由链，或“未见服务器重路由”。
- 本次/累计 Token、缓存输入比例、上下文占比、输出/推理 Token。
- 已运行时间、TTFT 状态、端到端速率和模型阶段估算速率。
- 行为学习或疑似降质详情。
- 子会话与子智能体。

将鼠标悬停在指标或使用 Tab 聚焦，即可查看名称边界和精确来源。

## 验证模型切换

1. 在一个 Terra 回合仍活动时，把任务选择切到 Sol。
2. 小狸应在约一秒内显示：

   ```text
   本回合 Terra · high（请求）
   下一回合 Sol · ultra（待生效）
   ```

3. 不要把当前回合后续片段误认为 Sol。开启下一回合。
4. 新 hook 或 `turn_context` 到达后，活动请求才应变成 Sol，待生效提示消失。

如果中途切换没有显示，请看 [模型切换没有出现](TROUBLESHOOTING.md#模型切换没有出现)。

## 调整窗口

- 从头像、模型行、Token 行、标题空白或六点抓手拖动。
- 从右下角抓手或系统窗口边缘缩放。
- `—` 隐藏到托盘。
- `… → 重置窗口位置` 将窗口恢复到当前屏幕右上角。
- `… → 状态与证据说明` 随时查看所有状态。
- `… → 退出小狸` 真正退出；下次 Windows/macOS/Linux 登录仍可按开机启动设置恢复。
