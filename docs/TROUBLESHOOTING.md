# 故障排查

## 点击刷新后看起来没有变化

刷新命令是后台单飞任务。按钮、托盘、watcher 和 hook 的重复请求会合并，避免并发重复扫描。

- 15 秒内完成：按钮直接采用命令返回的快照。
- 已有刷新运行：显示为合并，后台最多补一次尾随刷新。
- 15 秒未完成：按钮恢复并显示“本次刷新超时”，上一份有效快照继续可用；这不会伪装成红色采集故障。

如果窗口真的进入 Windows“未响应”，请记录版本、是否能拖动、`xiaoli --probe-once` 是否成功，并提交 issue。v0.1 已修复旧版“后台持刷新锁等待托盘主线程、主线程又等待刷新锁”的锁反转。

## Codex 正在运行但没有活动会话

1. 确认当前任务确实有尚未终止的回合。小狸列表只显示活动回合。
2. 执行 `xiaoli --probe-once`，查看 `codexRunning` 与 `conversations`。
3. 在 Codex 发送一条新消息，等待结构化 `task_started`/`turn_context`。
4. 执行 `xiaoli --install-plugin` 修复插件中的可执行文件绝对路径。
5. 检查状态说明是否出现“父会话未找到 / 层级异常”。小狸会保留孤立子任务，不会静默丢弃。

如果你从旧版本升级，V5 / 解析缓存格式 10 会重放 rollout 首部以恢复 `session_meta.model_provider`；首次重建可能短暂显示学习中或来源待确认。

## 模型切换没有出现

活动回合中切换模型不会改写当前请求。正确行为是立即显示 `pendingNextTurn`，到新回合开始后才更新 `activeRequest`。

如果连待生效状态也没有：

1. 运行 `xiaoli --install-plugin`。
2. 在 Codex `/hooks` 中审阅并信任 `xiaoli-model-monitor`；安装配置不会自动绕过 hook 信任确认。
3. 退出并重新启动 Codex，或开始一个新任务，使新 hook 配置加载。
4. 确认 hook 和 rollout 两条请求证据都能到达。
5. 用 `get_session_detail(threadId)` 检查 `activeRequest.source` 和 `pendingNextTurn`。

## 一直显示“未见服务器重路由”

这通常不是错误。它只表示小狸没有捕获明确 `model/rerouted` 事件。大部分未 reroute 回合都会保持这条文案。

小狸不会把请求模型写成服务器物理模型，也不会用速度、Token 或文本风格伪造 reroute。只有明确事件才显示服务器目标。

## TTFT 显示“等待首段”

首个 Reasoning/AgentMessage item 还没有完成，无法形成可信区间。完成后会显示 `约 A–B`。精确 TTFT 只有终态事件报告时才保存为基线样本。

如果一个完整回合结束后终态仍没有 `time_to_first_token_ms`，界面会说明字段缺失，不会用区间端点冒充精确值。

## 端到端或模型阶段速率缺失

- “等待输出”：尚无输出 Token。
- “等待模型片段”：还没有可合并的 Reasoning/AgentMessage 结构化区间。
- 字段缺失：rollout 版本没有提供对应结构化时间。

端到端速率包含网络、排队和工具等待；模型阶段速率是本地估算。两者都不等于服务端纯生成 TPS。

## 疑似降质没有出现

这是预期的保守行为。以下任一情况都会禁止触发：

- 同桶健康样本少于 30。
- 输出少于 128 Token。
- 只有一个异常信号。
- MAD 为零或字段不完整。
- 两个检查点间隔不足 2 秒，或输出增加不足 64 Token。
- 工具等待导致整回合变慢，但模型阶段没有两个独立异常。

不要为了“更敏感”而绕过这些门槛，否则网络和工具噪声很容易被误报为模型降级。

## 窗口拖不动、滚动跳动或窗口在屏幕外

- 从头像、模型行、Token 行、标题空白或六点抓手拖动；按钮、卡片和滚动区不会触发拖动。
- 列表只有一个原生滚动容器，不拦截滚轮。
- 选择托盘“重置到当前屏幕右上角”。
- 拔出显示器或修改 DPI 后，重新显示窗口会将其钳制到可见工作区。
- Wayland 的绝对定位和置顶取决于 compositor；可尝试 X11 会话确认差异。

## 连接来源一直是“未知”

`connectionOrigin` 不使用速度或回答风格猜测。以下情况会返回未知：

- 旧会话的 `session_meta.model_provider` 尚未完成缓存格式 10 回放。
- provider/base URL、hook endpoint 分类和环境/CLI 临时覆盖互相冲突。
- 第一方 endpoint 存在，但 `auth_mode` 不匹配或缺失。
- provider 配置使用小狸未识别的托管或本地命名。

先等待一次完整后台刷新，再展开工作台来源的 `evidence` 和 `limitations`。不要为了得到“官方”标签而删除冲突证据；未知是比误判更可靠的结论。

## 中转审计一直是“证据不足”

这通常是正确行为：

- 只运行了连接测试。
- 没有在本次审计中配置并实时调用同协议、同精确模型的第一方配对端点。
- 某些 fingerprint cell 有效回答少于 10，或目标/官方配对的可比质量 case 不足。
- 预算、超时、限流、取消或协议不支持使测试提前结束。
- 只导入了用户/社区参考摘要。当前 beta 的导入摘要仅作元数据显示，不参与 scorer，不能消除模型身份轴的证据不足。Release 内置社区分布即使给出“实验性地更接近”排名，也只是跨协议低置信附加证据，不会让身份轴变绿。
- 使用快速档查看行为质量。快速档只采集少量质量样本，不满足裁决门槛；即使有实时官方配对，质量轴也保持学习中。使用标准或深度档才会执行当前质量比较。

灰色不是“检测通过”。展开报告的四条证据轴查看缺少的实时参考或样本。未配对时协议和 usage 自洽检查仍可能有结果，但不能通过放宽门槛或导入摘要强制让模型身份变绿。

## 系统凭据库无法保存 API Key

小狸不会回退到明文文件。保存失败后，Key 仍只在当前进程内存：

- Windows：检查 Credential Manager 是否被组织策略禁用。
- macOS：查看 Keychain 是否锁定。
- Linux：确认当前桌面会话有可用的 Secret Service/DBus。

如果不想修复凭据库，可保持“只在内存”并在每次启动后手动输入。但内存 Key 不能用于跨重启定时审计。

## 中转审计取消后短暂仍显示运行中

取消标志会立即阻止开始下一个请求。正在系统网络栈内等待的单个请求需要等待取消或超时返回，因此 UI 可能短暂保留运行状态。使用有界 `timeoutMs`，并在报告中确认结论为 `cancelled`。

## Windows SmartScreen 或 macOS Gatekeeper 警告

`v0.2.0-beta.1` 没有正式代码签名或公证。ZIP 不会绕过平台保护。

1. 从项目 GitHub Release 下载。
2. 对照 `SHA256SUMS.txt`。
3. 使用系统自己的“更多信息/仍要打开”确认流程。

不要运行关闭 SmartScreen、Gatekeeper 或系统安全策略的脚本。

## 插件找不到可执行文件

便携程序移动目录后，插件仍可能引用旧绝对路径。直接从新目录启动小狸，或执行：

```text
xiaoli --install-plugin
```

然后在 Codex `/hooks` 中重新审阅命令。可执行文件路径改变会改变 hook 命令及其信任哈希；这一步不能由小狸代替用户确认。

## 收集诊断

请附上：

- 小狸版本和操作系统。
- `xiaoli --probe-once` 脱敏后的输出。
- 具体状态 code 和 explanation。
- 是否是 X11/Wayland，多显示器与 DPI 情况。
- 可复现步骤。

不要上传 Codex rollout、真实 prompt/回复、浏览器 profile、SQLite 或包含私人路径的截图。
