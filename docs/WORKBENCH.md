# 小狸工作台使用指南

工作台是 `v0.2.0-beta.1` 新增的本地标准窗口。它用于长时间查看会话指标、连接来源和中转审计报告；不代替默认置顶的小型监视窗。

> 只对你拥有或获得授权测试的 endpoint 发起主动审计。每一次审计都会产生真实 API 请求与费用。

## 打开与窗口行为

- 在托盘右键菜单选择“打开工作台”，或从小窗 `…` 菜单进入。
- 默认大小 `1180 × 760 DIP`，最小 `960 × 640 DIP`。
- 使用系统标题栏和任务栏，不置顶。关闭工作台不会终止小型监视窗或托盘进程。
- 主动审计使用独立 `AuditManager`；扫描、网络与 SQLite 工作不在 WebView/UI 线程执行，也不占用 Codex 采集的 `refresh_guard`。

## 页面一：总览

总览页同时展示：

- 活动根会话和子智能体的去重汇总。
- 本回合的请求模型、请求 effort、Token、缓存输入占比与采集状态。
- `officialChatGpt / officialOpenAiApi / officialAnthropicApi / managedProvider / customEndpoint / localEndpoint / unknown` 来源分类。
- 协议兼容、计量一致性、行为质量和模型身份四条审计证据轴。
- 最近的待确认、明确矛盾或证据不足提示。

来源分类只描述“当前配置指向哪类端点”，不描述物理模型。自定义端点也不自动等于恶意中转。

## 页面二：会话历史

每个 thread/turn 只保存派生记录：

- 经截断的 thread/turn ID；当前 beta 以“时间 + 短 ID”作为历史显示名，不持久化自动任务标题，也尚未提供本地别名编辑。
- 请求模型、请求 effort、来源分类和显式 reroute 证据标记。
- 输入、输出、推理、缓存输入和总 Token，以及 TTFT、时长和观测速率。
- 根任务/子智能体层级、状态级别和结束时间。

不保存自动抓取的完整任务标题、prompt、回复、命令/工具正文或完整 cwd。默认保留 180 天，可选 30 天、90 天或永久。更改保留期只影响派生历史，不删除 Codex 原始 rollout。

## 页面三：中转检测

### 创建 `RelayProfile`

1. 输入本地显示名称。
2. 选择 OpenAI Responses、OpenAI Chat Completions 或 Anthropic Messages。
3. 输入 Base URL。保存时会去除 userinfo、query 和 fragment。非 localhost 的明文 HTTP 端点可以保存，但每次手动连接测试或审计前都必须单独确认可能被窃听的风险；定时审计会拒绝它。
4. 输入要请求的精确模型 ID。这是 `claimedModel`，不是小狸测出的 `actualModel`。
5. 输入你自己的 API Key。小狸不读取、不复用 Codex ChatGPT OAuth token 或 Codex 配置里的 Key。
6. 可选填一个本地私有 probe pack 的绝对路径。保存成功后页面显示版本与 SHA-256 前 8 位；点击“清除”后还需要保存配置才能生效。

API Key 默认只在当前进程内存。勾选“保存到系统凭据库”是一次明确授权：Windows 使用 Credential Manager，macOS 使用 Keychain，Linux 使用 Secret Service。系统凭据库不可用时，小狸显示警告并回退到内存，不创建明文凭据文件。

私有题包只把规范化路径、版本和 SHA-256 写入 profile 与审计报告，任务正文不会进入 SQLite、日志或报告。每次审计开始前会重新读取并核对哈希；文件缺失或内容变化会在发出任何请求前拒绝启动。题包任务与内置探针共享同一预算硬上限，格式与 scorer 边界见 [中转审计方法](RELAY_AUDIT.md#用户私有-probe-pack)。

### 连接测试

连接测试不超过 6 次请求，用于认证、基础非流式响应与 SSE。它不建立质量/指纹结论。

### 一键审计

| 档位 | 默认指纹单元 | 单 endpoint 硬上限 |
| --- | ---: | ---: |
| 快速 | 8 × 15 | 150 次请求 |
| 标准 | 16 × 15 | 320 次请求 |
| 深度 | 40 × 15 | 720 次请求 |

开始前必须查看并确认请求、输入 Token、输出 Token 和超时上限。确认框会单列私有题包增加的请求数和保守输入/输出额度，并显示完整计划的每端点请求数；官方配对时总操作数为相同计划 × 2。网络尝试计入硬上限，完整计划超过任一预算时会在发请求前拒绝，不能靠截断随机挤掉内置或私有探针。官方配对必须另行配置同协议、同精确模型的第一方 profile 与独立凭据，会产生额外请求。只有这次审计实时得到的官方配对样本会进入统计比较。

不启用官方配对时，小狸仍会执行协议检查、usage 算术自洽检查，并采集目标端六个确定性探针域：结构化 JSON、长上下文随机 nonce 检索、算术/约束推理、多语言、工具选择和状态保持。工具域按所选协议发送真实工具 schema，只解析并评分受限的结构化函数名/字符串参数，绝不执行工具、URL 或代码，也不持久化原始响应正文；状态保持只验证同一请求所携带的 `system / user / assistant / user` 多消息历史，不表示跨网络会话状态或物理模型身份。因为没有对照，当前 beta 不把这些目标端结果解释为“相对官方降质/一致”；行为质量保持灰色学习中/证据不足，模型身份轴也保持灰色。

报告详情在四轴下方单独显示“真实会话对照”。只有主动审计与实时匹配参考一致，且同一本地 profile 的最近 30 天真实完成回合满足保守门槛时，才会黄色显示“疑似选择性服务”。该状态不改写四轴或总结论；点开后可查看样本数、异常数、占比、时间窗口、判定原因和证据限制。

快速档每个质量域只采集两个批次中的少量样本，用来验证链路和保留观察，不满足当前质量裁决所需的每域样本门槛；即使启用官方配对，质量轴也保持学习中。标准档每域每批 4 个、深度档每域每批 8 个配对样本，才会进入当前的 99% bootstrap 质量比较。

取消后不再开始新请求，已完成证据可保留为 `cancelled` 报告。请求已在操作系统网络栈内等待时，终止速度受传输层取消/超时影响。

## 页面四：参考资料

列表展示导入摘要的：

- 来源：`official / community / user`。
- 模型、协议、版本、样本数、创建/过期时间和参数限制。
- 签名标记是否已经验证。

三种来源分区存储。中转响应不能更新官方或社区命名空间。`v0.2.0-beta.1` 对用户导入包只进行 JSON 结构和大小校验，并默认标记为“未签名”；这些 `RelayBaselineSummary` 只是本地参考元数据，**不进入当前审计 scorer，也不会出现在官方配对下拉框中**。Release 内置的版本化社区分布是另一条只读路径：它只在无实时官方配对时附加低置信、跨协议实验排名，不改变证据轴或总裁决。

“官方”来源的摘要也不等于实时官方对照。当前 beta 真正参与统计评分的参考只来自用户在同一次审计中明确选择并授权调用的第一方 profile；目标和官方端点使用相同协议、精确模型和探针参数。

浮动模型别名、不同 system prompt、推理参数、量化方式、provider 和模型更新都可能让摘要失去参考意义；页面会保留时效/限制供人工判断。当前 beta 不会因为导入摘要看似匹配就提升 scorer 置信度。

## 页面五：检测原理

该页是报告口径的应用内版本：

- 绿：对应证据轴的前置条件满足且本次范围内未见异常。行为质量只有标准/深度档启用实时官方配对后才可能显示“与参考一致”；模型身份也需要实时官方配对。两者仍不是物理模型证明。
- 黄：疑似过量计数、疑似降质或分布显著偏离，必须展开原因、样本数与限制。
- 红：可复现的协议或 usage 契约矛盾。
- 灰：证据不足、没有实时匹配参考、参数不可控、取消或不支持。未启用官方配对时，协议/usage 自洽检查仍可有结果，但相对行为质量与模型身份必须保持灰色。

完整方法和抗规避限制见 [中转审计方法](RELAY_AUDIT.md)。

## 定时检查

默认关闭。启用后必须绑定一个已保存的 profile 和可从系统凭据库读取的凭据；内存 Key 不能跨重启运行。默认使用快速档，在用户选定的本地时间附近随机抖动 ±30 分钟，并受每次与每月请求硬上限保护。保存前会重新验证私有题包并预览完整快速计划，确认框明确显示内置请求数、题包增加数、每端点计划数及官方配对后的总操作数；超出每次预算会拒绝启用，不会截断题包或挤掉内置探针。官方配对需要单独勾选，配对时每月上限最小 300 次，未配对时最小 150 次。页面显示预算月份、已预留、上限和剩余额度；这里的“预留”是防止并发/重启突破上限，不是服务商账单。

修改系统时钟、休眠、网络不可用或凭据库锁定可能让当次计划返回失败/证据不足；小狸不会为了“补跑”突破月度预算。

## 报告与删除

审计报告保存以下结构化证据：参数、CSPRNG `runSeed`、请求/样本计数、四轴状态、原因、置信度与限制。不保存原始探针 prompt、原始回复正文或 API Key。详情卡会在字段存在时展示 usage 的被测端点/官方参考置信区间与容差、质量参考有效 case/失败域、可比较指纹 cell、平均 JSD，以及后端实际提供的 MMD 效应量/p 值；每条黄色原因与限制通过可点击、可键盘聚焦的展开区显示。

删除 profile 会删除对应的内存/系统凭据引用，但已有报告为了可复核性默认保留，直到用户显式删除。报告列表支持逐条删除；该操作只删除所选报告及其内存终态快照，不影响端点配置、系统/内存凭据或任何会话历史。

## 平台注意事项

- Windows 未签名 beta 可能显示 SmartScreen；先校验 `SHA256SUMS.txt`，再使用系统“更多信息”流程。
- macOS beta 采用 ad-hoc 签名、未公证；校验后使用“隐私与安全性 → 仍要打开”。
- Linux Wayland 下小窗置顶、托盘和绝对定位取决于 compositor；工作台的普通窗口与后台审计不依赖绝对定位。
